1. C'est quoi l'authentification ?

[PROG] objectif : « définir la notion d'authentification ».

📘 Définition

Authentification = prouver qui tu es (login + mot de passe, ticket, certificat…). Exemple : à l'entrée d'une boîte de nuit, le videur vérifie ta carte d'identité. C'est ça.

À ne pas confondre : authentification = qui es-tu ? · autorisation = qu'as-tu le droit de faire ? (les droits sur un dossier partagé, par ex.). L'authentification vient toujours en premier. [+] (voir ta fiche AAA Cisco pour le 3ᵉ A : Accounting).

💡 Où ça se passe dans Windows Server ?

Dans un domaine Active Directory, l'identité est vérifiée par le contrôleur de domaine (DC). Active Directory = annuaire (LDAP) + Kerberos (authentification) + NTP (horloges synchronisées). [KRB p.12]

2. Groupes et stratégie de groupes

[PROG] : « groupes de distribution, groupes de sécurité, stratégie de groupes restreints ». Idée simple : au lieu de donner des droits à 200 personnes une par une, on les met dans un groupe et on donne le droit au groupe.

TypeSert à…Exemple
Groupe de distributionEnvoyer des mails à plusieurs personnes. Ne donne AUCUN droit d'accès.Liste « tous-les-profs »
Groupe de sécuritéDonner des permissions (dossiers, imprimantes) et peut aussi servir de liste mail.Groupe « Comptables » → lecture sur \\SERVER1\compta
Groupes restreints (Restricted Groups)Paramètre de GPO qui impose qui est membre d'un groupe (ex. Administrateurs locaux). Si quelqu'un s'ajoute à la main, la GPO le retire. [+]Seul « Admins-IT » reste admin local des PC
💡 Astuce mémoire

Distribution = Diffusion de mails. Sécurité = Serrure (droits).

Les 3 portées d'un groupe ([+] notion classique AD) : Locale de domaine (reçoit les droits), Globale (regroupe des utilisateurs), Universelle (toute la forêt). Règle AGDLP : Comptes → Globaux → Domain Local → Permissions.

3. Les relations d'approbation (trusts)

3.1 Pourquoi ?

[C03 §1] Une entreprise a plusieurs filiales avec des domaines différents. Une approbation est un lien de confiance : un utilisateur authentifié dans SON domaine peut accéder aux ressources d'un AUTRE domaine sans créer un 2ᵉ compte. Exemple : un employé de Paris ouvre un dossier partagé de Lyon avec son compte parisien.

3.2 Les 2 propriétés à connaître par cœur

⭐ Direction & Transitivité

Direction : unidirectionnelle (1 sens) ou bidirectionnelle (2 sens). [C03]

Transitivité : si A approuve B et B approuve C ⇒ A approuve C automatiquement. Comme un ami d'un ami devient ton ami. [C03]

🪤 Le piège du sens (le plus fréquent !)

Règle simple : l'approbation sortante (outgoing) = « MOI j'approuve l'autre » ⇒ les utilisateurs de l'autre viennent chez moi. L'approbation entrante (incoming) = « l'autre m'approuve » ⇒ mes utilisateurs vont chez lui. Les deux se créent des deux côtés : entrante d'un côté ⇒ sortante de l'autre. [C03 : écran « Sides of Trust »]

Exemple [C03] : sur utopia.net on choisit « One-way: incoming » car nos utilisateurs doivent s'authentifier dans supinfo.lan.

3.3 Les 4 types d'approbation

TypeComment elle naîtSens / TransitiveÀ quoi ça sert
Prédéfinie : parent/enfantAutomatique quand on ajoute un domaine enfant (ex. lyon.supinfo.lan sous supinfo.lan)Bidirectionnelle + transitiveRelier les domaines d'une même arborescence
Prédéfinie : arborescence (tree-root)Automatique entre la racine d'une nouvelle arborescence et la racine de la forêt (ex. deciplex.lan)Bidirectionnelle + transitiveAjouter une « sous-forêt »
Raccourcie (shortcut)ManuelleTransitiveGagner du temps : sans elle, l'authentification parcourt toute la chaîne de domaines (lent). Ex. lyon.supinfo.lan ↔ lyon.utopia.net en direct
ExterneManuelle, vers un domaine hors forêtuni ou bi · NON transitiveMigrations d'utilisateurs, accès à un seul domaine d'une autre forêt (pas toute la forêt)
ForêtManuelle, entre les 2 racines de forêtuni ou bi · TransitiveTous les domaines d'une forêt approuvent tous ceux de l'autre via UN seul lien. Exige le niveau fonctionnel 2003+/2008 [STR §4.2]

[+] Aussi mentionnés par l'assistant [C03 p.6] : approbation avec un domaine Windows NT 4.0 ou un royaume Kerberos V5 (Unix/MIT) — non transitive.

⭐ Externe vs Forêt en 10 secondes

Externe = 1 domaine ↔ 1 domaine, pas de transitivité. Forêt = racine ↔ racine, transitive pour toute la forêt.

4. TP pas à pas (comme pour un débutant complet)

4.A Créer une approbation FORÊT unidirectionnelle [C03 §3]

Situation : forêts supinfo.lan et utopia.net. On veut que les utilisateurs de utopia.net accèdent aux ressources de supinfo.lan. On travaille sur le serveur de utopia.net.

Gestionnaire de serveur → Tools → Active Directory Domains and Trusts (« Domaines et approbations Active Directory »).
Clic droit sur utopia.net → Properties → onglet Trusts → bouton New Trust… puis Next.
Name : tape le domaine auquel on veut accéder : supinfo.lan (nom DNS obligatoire pour une forêt).
Trust Type : coche Forest trust.
Direction : One-way: incoming (nos utilisateurs s'authentifient là-bas).
Sides of Trust : Both this domain and the specified domain = crée aussi le côté sortant chez supinfo.lan, sans y aller. Il faut alors un compte admin de supinfo.lan.
Saisis Administrator + mot de passe de supinfo.lan.
Outgoing Trust Authentication Level : Forest-wide authentication (toutes les ressources, conseillé si même organisation) ou Selective authentication (rien n'est autorisé automatiquement, on donne l'accès serveur par serveur : conseillé si organisations différentes).
Récapitulatif (Direction incoming, Forest trust, Transitive : Yes) → Next. Confirm incoming trust → « No, do not confirm » → Next → Finish.
Valider : sur supinfo.lan → Properties → Trusts → sélectionne l'approbation → Properties → Validate. Message attendu : « The trust has been validated. It is in place and active. »

4.B TP complet : 2 domaines + approbation externe bidirectionnelle [STR]

Plan : SERVER1.LES-COMORES.KM (192.168.3.20) et SERVER2.TSINIMOICHONGO.KM (192.168.3.10), Windows Server 2008. Comptes de test : Le-comorien@les-comores.km et Halima@tsinimoichongo.km.

🪤 Les 3 erreurs qui font tout planter

1) DNS mal configuré ⇒ les 2 serveurs ne se voient pas. 2) Horloges/fuseaux différents ⇒ Kerberos refuse (voir §5). 3) Oublier de configurer la redirection DNS sur les DEUX serveurs. [STR p.18, p.31]

Nom + IP fixe : renomme la machine (SERVER1), IP statique.
Installer le rôle DNS : Gestionnaire de serveur → Rôles → Ajouter des rôles → cocher Serveur DNS → Installer.
Promouvoir en contrôleur de domaine : Exécuter → dcpromo. Mode avancé non coché. Choisis « Créer un domaine dans une nouvelle forêt » (important : chaque serveur = SA forêt), nom Les-comores.km, niveau fonctionnel Windows Server 2008, laisse DNS + catalogue global cochés. Message « délégation DNS impossible » → Oui (normal). Garde les chemins par défaut (NTDS, SYSVOL). Définis le mot de passe de restauration et ne l'oublie pas. Redémarre.
Zone inverse DNS : Outils d'administration → DNS → Zones de recherche inversée → Nouvelle zone → principale, intégrée AD, IPv4, ID réseau 192.168.3, mises à jour sécurisées seulement.
Enregistrement PTR : clic droit sur la zone inverse → Nouveau pointeur (PTR) → IP 192.168.3.20 → Parcourir jusqu'à server1. Test : nslookup doit répondre server1.les-comores.km ↔ 192.168.3.20.
Refaire TOUT sur SERVER2 (IP 192.168.3.10, forêt Tsinimoichongo.km), puis tester son nslookup. « Sinon pas la peine » : l'approbation en dépend.
Redirecteurs DNS : DNS → clic droit serveur → Propriétés → Redirecteurs → Modifier → ajoute l'IP de l'autre serveur (SERVER1 → 192.168.3.10, et inversement). Vérifie la coche verte « Validé ».
Créer les utilisateurs : Utilisateurs et ordinateurs AD → Users → Nouveau → Utilisateur (le-comorien ici, halima sur SERVER2).
Créer l'approbation (sur SERVER1 seulement) : Outils d'administration → Domaines et approbations AD → Propriétés de Les-comores.km → onglet Approbations → Nouvelle approbation → nom TSINIMOICHONGO → type Externe → sens Bidirectionnel → « Ce domaine et le domaine spécifié » → compte Administrateur de SERVER2 → authentification pour toutes les ressources → confirmer l'approbation sortante OUI et entrante OUI → Terminer.
Valider : Propriétés de l'approbation → Valider → « Oui, valider l'approbation entrante » + admin de l'autre domaine. Refais pour l'autre sens. Le tableau montre : Type = Externe, Transitif = Non.
Partage de test : dossier DOSSIER_PARTAGE → Propriétés → Partage avancé → Partager → Autorisations → Ajouter les comptes des deux domaines (changer l'Emplacement pour l'autre domaine). Répète dans l'onglet Sécurité (NTFS).
Test : depuis SERVER2 : Exécuter → \\192.168.3.20 ⇒ on voit le dossier. Un client Windows 7 (DHCP 192.168.3.22-24) joint à Les-comores.km se connecte avec le-comorien ou TSINIMOICHONGO\halima (format DOMAINE\utilisateur, car halima n'existe pas dans le domaine joint).
📝 Remarque

Dans [STR p.35] l'étendue DHCP affiche « 192.168.2.24 » et « passerelle 192.168.2.1 » dans le texte alors que la capture montre 3.24 / 3.1 : c'est une faute de frappe, le réseau est 192.168.3.0/24.

💡 Filtrage SID [STR p.26 · PROG]

Sur une approbation externe, Windows active par défaut le filtrage SID : un utilisateur migré porte l'ancien SID (SID History) ; sans filtre, quelqu'un pourrait usurper le SID d'un admin (« usurpation de SID » du programme). Le filtre ignore les SID étrangers au domaine approuvé. On ne le désactive que pour une migration.

4b. TP : domaine parent/enfant, groupes, GPO

Sources : [TP-ADM] « Domaine parent/enfant, groupes et GPO » · [TP-PE] « Authentification cross-domain Parent → Enfant » · [TP-GPO] « TP avancés GPO ».

4b.1 Construire la forêt (parent + enfant) [TP-ADM ét.1-4]

📘 Idées de base

Forêt = la frontière de sécurité. Domaine parent = la racine de toute la structure. Domaine enfant (ex. alger.entreprise.local) hérite du DNS du parent et reçoit automatiquement une approbation bidirectionnelle + transitive.

ParentDC : IP statique 192.168.1.10, masque 255.255.255.0, passerelle 192.168.1.1, DNS = lui-même (192.168.1.10).
ChildDC : IP 192.168.1.20, mais DNS = ParentDC (192.168.1.10). Sinon il ne trouve pas la forêt. Teste avec ping 192.168.1.10.
Sur ParentDC : Gestionnaire de serveur → Ajouter des rôles → AD DS → Installer → Promouvoir en contrôleur de domaine → Créer une nouvelle forêt → entreprise.local → mot de passe DSRM (restauration) → redémarrage.
Sur ChildDC : installe AD DS → Promouvoir → Ajouter un domaine à une forêt existante → Domaine enfant → parent entreprise.local, enfant alger → compte admin de ParentDC → DNS coché → redémarrage.
Groupes/utilisateurs (Utilisateurs et ordinateurs AD) : sur ParentDC groupe de sécurité IT-Parent + utilisateur AdminParent membre ; sur ChildDC IT-Child + AdminChild. Option : groupe restreint via GPO pour mettre AdminChild admin local de tous les PC de l'enfant.

4b.2 GPO de mot de passe [TP-ADM ét.5]

ParentDC → gpmc.msc → clic droit sur le domaine → Créer un GPO → PasswordPolicy-Parent.
Longueur minimale 8 · historique 5 mots de passe · durée maximale 90 jours.
Lie-la au domaine, puis gpupdate /force et vérifie avec net user NomUtilisateur /domain.
🪤 Attention (complément [+])

Une stratégie de mot de passe liée à entreprise.local s'applique aux comptes de CE domaine. Le domaine enfant n'en hérite pas : chaque domaine a sa propre stratégie de mot de passe. Si le TP te demande de tester sur un utilisateur de l'enfant, crée aussi une GPO sur alger.

4b.3 Tester l'approbation parent → enfant [TP-PE]

But : Alice (compte parent.com\Alice) accède à un partage de l'enfant sans compte créé dans l'enfant.

Sur le serveur enfant : Active Directory Domains and Trusts → clic droit sur le domaine enfant → Properties → Trusts : le parent est listé, bidirectionnel + transitif.
Crée C:\Docs → Propriétés → Partage → Partage avancé → Partager, nom Docs.
Permissions → Ajouter → Emplacement → choisir le domaine parent → ajoute Alice (ou mieux un groupe qui la contient) → Lecture/Écriture.
Connecte-toi sur une machine de l'enfant en parent.com\Alice, ouvre \\enfant\Docs, crée/modifie un fichier.
Preuve (option) : Observateur d'événements → Sécurité → ID 4624 montre parent.com\Alice authentifiée via le trust. Teste aussi whoami /groups (cas AdminChild sur ParentDC).

4b.4 Sécurité de base [TP-ADM ét.7]

Mises à jour Windows installées · MBSA sur les 2 serveurs · test du verrouillage de compte · test de la GPO mot de passe. [+] MBSA est un outil ancien (plus maintenu par Microsoft) : en pratique on utilise Windows Update/WSUS et d'autres scanners, mais il reste au programme.

5. Les méthodes d'authentification : Kerberos, LanManager, RADIUS

[PROG] : « authentification entre forêts, avec serveurs non-Windows, usurpation de SID, filtrage SID, LanManager, Kerberos, Radius ».

5.1 Kerberos : le principe [KRB]

Protocole d'authentification sur réseau non sûr, basé sur la cryptographie à clé symétrique. Il donne : confidentialité, intégrité, authentification mutuelle, protection contre le rejeu. Nom = Cerbère, chien à 3 têtes des Enfers (mythologie). Né au MIT (projet Athena, 1983) ; v4 fin des années 80 (DES 56 bits) ; v5 en 1993 (RFC 1510, remplacé par le RFC 4120 en 2005). Windows 2000 l'a intégré à Active Directory.

MotExplication simple
Royaume (realm)Le réseau protégé, nom en MAJUSCULES, dérivé du domaine : IRISA.FR. Dans AD : le domaine.
PrincipalUne identité : utilisateur, machine ou service. Format user@REALM, host/lepton.irisa.fr@IRISA.FR. Chacun a une clé (celle d'un utilisateur est dérivée de son mot de passe + le royaume = « salage »).
KDC (Key Distribution Center)Le serveur de confiance, composé de AS (Authentication Server : donne les TGT) et TGS (Ticket Granting Server : donne les tickets de service). Dans AD = le contrôleur de domaine. Si le KDC tombe/est piraté, tout tombe.
TGTTicket initial, obtenu avec le mot de passe, valide ~24 h. C'est ta « carte d'identité » pour demander d'autres tickets.
Ticket de service (TS)Ticket pour un service précis. Demandé avec le TGT sans retaper le mot de passe.
Credential cacheL'endroit où les tickets sont rangés (fichier chez MIT/Heimdal, mémoire chez Microsoft).
⭐ Le film en 3 actes (analogie parc d'attractions)
1 Je donne mon mot de passe à l'AS→reçois un TGT 🎟️ (bracelet du parc)→2 Je montre le TGT au TGS→reçois un ticket de service (ticket de manège)→3 Je présente ticket + authentifieur chiffré au service→accès ✅

L'authentifieur (chiffré avec la clé de session, contient l'horodatage) prouve que c'est bien moi maintenant. [KRB p.30-48 ; détail des étapes : schémas du PDF]

5.3 LanManager / NTLM et RADIUS

LAN Manager (LM) : très vieille méthode, hachage faible des mots de passe ⇒ à désactiver. NTLM (v1 puis v2) : défi/réponse, utilisé en secours quand Kerberos est impossible (ex. accès par adresse IP au lieu du nom). Kerberos = méthode par défaut d'un domaine moderne. [TP-LM + +]

RADIUS : serveur central qui authentifie les accès réseau (Wi-Fi, VPN, 802.1X), UDP 1812/1813, seul le mot de passe est chiffré. [+ ta fiche AAA] Windows l'offre via le rôle NPS.

AAA · 1. Les 3 A de l'AAA

📘 Définition — AAA

[AAA] AAA = cadre de sécurité des équipements réseau (routeurs, switches, pare-feux) pour contrôler qui accède à l'équipement, ce qu'il a le droit d'y faire, et garder une trace de ce qu'il y a fait.

  • Authentication (authentification) — Qui es-tu ?
  • Authorization (autorisation) — Qu'as-tu le droit de faire ?
  • Accounting (traçabilité) — Qu'as-tu fait, et quand ?
💡 Analogie de l'hôtel

Réception : on vérifie ta pièce d'identité (authentification) → ta carte n'ouvre que ta chambre (autorisation) → le registre note tes entrées/sorties (accounting).

ComposantQuestionCe qu'il contrôleExemple
AuthenticationQui es-tu ?Identité (identifiant + mot de passe, certificat, clé…)Login sur la console d'un routeur
AuthorizationQu'as-tu le droit de faire ?Commandes/ressources autorisées une fois authentifiéTechnicien : niveau 1 ; admin : niveau 15
AccountingQu'as-tu fait ?Journalise connexions, durée, commandes« admin1 connecté à 10h02, a tapé reload à 10h15 »
💡 Ordre à mémoriser

Toujours : vérifier l'identité → vérifier les droits → enregistrer l'activité. On n'autorise pas quelqu'un qu'on n'a pas encore authentifié.

1.1 Pourquoi mettre en place l'AAA ?

Sans AAA, un équipement Cisco n'a qu'un mot de passe de ligne identique pour tous, sans nom d'utilisateur, sans journal, sans distinction de droits. L'AAA apporte :

  • un identifiant individuel par administrateur (traçabilité nominative)
  • une gestion centralisée possible (un serveur pour tout le réseau)
  • un contrôle fin des droits (qui tape quelles commandes)
  • une journalisation des actions, utile pour les audits
  • un mécanisme de secours (fallback) si le serveur est injoignable

1.2 Deux grands modes

ModeOù sont les comptes ?AvantageLimite
AAA localeDans la config de l'équipement (username)Marche sans réseau ni serveurPas centralisé : à recréer sur chaque équipement
AAA serveur — TACACS+Serveur externe (Cisco ACS, ISE, tac_plus…)Contrôle très fin des commandes (device administration)Dépend du serveur et du réseau
AAA serveur — RADIUSServeur externe (FreeRADIUS, Cisco ISE…)Standard ouvert : accès réseau (Wi-Fi, VPN, 802.1X)Moins fin pour les commandes CLI

AAA · 2. Lignes d'accès et listes de méthodes (method lists)

LigneCommandeUsage
Consoleline console 0Accès physique par câble console
VTYline vty 0 4 (ou 0 15)Accès distant (Telnet / SSH)
AUXline aux 0Accès distant par modem (rare aujourd'hui)
📘 Liste de méthodes (method list)

La séquence de méthodes (authentification, autorisation ou accounting) que le routeur essaie dans l'ordre jusqu'à ce que l'une réponde. Deux formes :

  • default — s'applique automatiquement aux lignes sans liste explicite
  • nommée (ex. CONSOLE-AUTH) — à appliquer à la main sur chaque ligne avec login authentication <nom>
aaa authentication login {default | NOM-LISTE} méthode1 [méthode2] [méthode3] …

Le routeur essaie méthode1 ; si le serveur ne répond pas (timeout), il passe à méthode2, etc. Si une méthode répond mais refuse (mauvais mot de passe), il n'essaie pas la suivante : accès refusé.

Mot-cléSignification
localBase d'utilisateurs locale (username)
group tacacs+Serveur(s) TACACS+ déclaré(s)
group radiusServeur(s) RADIUS déclaré(s)
group NOM-GROUPEGroupe de serveurs personnalisé (sous-ensemble)
enableMot de passe enable en secours
noneAccès sans authentification (à éviter, sauf test)
🪤 Erreur fréquente

Liste nommée créée mais jamais appliquée avec login authentication <nom> : la ligne garde l'ancien mode, la liste n'a aucun effet.

💡 Astuce

Toujours une méthode de secours (local ou enable) après group tacacs+ / group radius, pour ne pas être bloqué dehors si le serveur tombe.

AAA · 3. AAA locale — console et lignes vty

[AAA] TP « AAA locale console & vty » : la base d'utilisateurs est dans la configuration du routeur/switch, sans serveur externe.

Détail
✅ AvantagesSimple ; marche même si réseau ou serveur en panne ; aucune dépendance externe
⚠️ InconvénientsPas centralisé (une base par équipement) ; pénible sur un grand parc ; pas de journal centralisé

Étapes pas à pas

Activer le modèle AAA (sans lui, toutes les commandes aaa … sont indisponibles).
Router(config)# aaa new-model
Créer les comptes locaux avec secret (jamais password en clair).
Router(config)# username admin privilege 15 secret Cisco12345
Router(config)# username technicien privilege 1 secret Tech12345
Créer la liste de méthodes. Option A — default (applicable partout) puis Option B — liste nommée (à appliquer à la main).
Router(config)# aaa authentication login default local
Router(config)# aaa authentication login CONSOLE-AUTH local
Appliquer sur la console. Avec la liste default, login authentication est facultatif (déjà automatique).
Router(config)# line console 0
Router(config-line)# login authentication CONSOLE-AUTH
Router(config-line)# exec-timeout 5 0
Appliquer sur les lignes vty (accès distant). Limite à ssh : le Telnet envoie les identifiants en clair.
Router(config)# line vty 0 4
Router(config-line)# login authentication CONSOLE-AUTH
Router(config-line)# transport input ssh
Vérifier, puis déconnecte-toi et reconnecte-toi (console ou SSH) : identifiant et mot de passe doivent être demandés.
Router# show running-config | section line
Router# show running-config | include aaa|username

Exemple de configuration complète

Router(config)# aaa new-model
Router(config)# username admin privilege 15 secret Cisco12345
Router(config)# aaa authentication login default local
Router(config)# line console 0
Router(config-line)# exec-timeout 5 0
Router(config-line)# exit
Router(config)# line vty 0 4
Router(config-line)# transport input ssh
Router(config-line)# exit
⭐ À retenir — AAA locale
  • Toujours username … secret ….
  • aaa new-model = préalable obligatoire.
  • default s'applique seule ; une liste nommée s'applique avec login authentication <nom>.

AAA · 4. AAA serveur — TACACS+ et RADIUS (console)

[AAA] TP « AAA serveur TACACS+ / RADIUS console » : l'authentification (et autorisation, accounting) est déléguée à un serveur externe (Cisco ACS / ISE, tac_plus, FreeRADIUS…).

4.1 TACACS+ vs RADIUS

CritèreTACACS+RADIUS
OriginePropriétaire CiscoStandard ouvert (RFC 2865/2866)
TransportTCP, port 49UDP, ports 1812 (authentification) et 1813 (accounting)
ChiffrementTout le paquetUniquement le mot de passe
Séparation des 3 AAuthentification, autorisation, accounting séparésAuthentification + autorisation combinées
Autorisation par commande✅ Oui (commandes CLI, niveau par niveau)❌ Non, pas nativement
Usage typiqueAdministration des équipements (qui tape quelles commandes)Accès réseau des utilisateurs (Wi-Fi, VPN, 802.1X)

4.2 Configuration TACACS+

Déclarer le serveur
Router(config)# tacacs server SRV-TACACS
Router(config-server-tacacs)# address ipv4 192.168.1.10
Router(config-server-tacacs)# key Cisco123secret
Router(config-server-tacacs)# exit
(Optionnel) Regrouper le serveur dans un groupe
Router(config)# aaa group server tacacs+ TAC-GROUP
Router(config-sg-tacacs+)# server name SRV-TACACS
Router(config-sg-tacacs+)# exit
Activer AAA + liste d'authentification. local après group tacacs+ = secours si le serveur ne répond pas.
Router(config)# aaa new-model
Router(config)# aaa authentication login default group tacacs+ local
Appliquer sur la console
Router(config)# line console 0
Router(config-line)# login authentication default
Autorisation et accounting (spécifiques TACACS+). Le niveau commands 15 (par commande) ne marche qu'avec TACACS+.
Router(config)# aaa authorization exec default group tacacs+ local
Router(config)# aaa authorization commands 15 default group tacacs+ local
Router(config)# aaa accounting exec default start-stop group tacacs+
Router(config)# aaa accounting commands 15 default start-stop group tacacs+

4.3 Configuration RADIUS

Déclarer le serveur
Router(config)# radius server SRV-RADIUS
Router(config-radius-server)# address ipv4 192.168.1.20 auth-port 1812 acct-port 1813
Router(config-radius-server)# key testing123
Router(config-radius-server)# exit
Activer AAA + liste
Router(config)# aaa new-model
Router(config)# aaa authentication login default group radius local
Appliquer sur la console
Router(config)# line console 0
Router(config-line)# login authentication default
Accounting (RADIUS : pas d'accounting détaillé par commande).
Router(config)# aaa accounting exec default start-stop group radius
⭐ À retenir — AAA serveur
  • Déclarer le serveur (tacacs server / radius server) avec sa clé partagée avant la liste d'authentification.
  • Garder local en secours après group tacacs+ / group radius.
  • Seul TACACS+ permet le contrôle fin des commandes par niveau de privilège.

AAA · 8. À retenir — l'essentiel

🧠 Les 7 points essentiels
  1. AAA = Authentication (qui es-tu) + Authorization (qu'as-tu le droit de faire) + Accounting (qu'as-tu fait).
  2. aaa new-model : préalable obligatoire.
  3. Une liste de méthodes essaie chaque méthode dans l'ordre, et passe à la suivante seulement si le serveur ne répond pas (pas en cas de refus).
  4. AAA locale : pas de dépendance réseau, mais pas centralisée.
  5. TACACS+ (TCP/49, tout chiffré) : administration des équipements, contrôle fin des commandes.
  6. RADIUS (UDP/1812-1813, mot de passe chiffré) : standard ouvert, accès réseau des utilisateurs.
  7. Toujours une méthode de secours local après un serveur externe.

Révision — Authentification, approbations, Kerberos

Q1. Approbation créée automatiquement, bidirectionnelle et transitive ?

Prédéfinie (parent/enfant et arborescence). [C03]

Q2. Pourquoi créer une approbation raccourcie ?

Éviter le long parcours de la chaîne de domaines. [C03 §2.2]

Q3. Externe ou forêt : laquelle est transitive ?

Forêt. L'externe ne l'est pas. [C03 · STR]

Q4. Que contiennent le KDC et que délivre chaque partie ?

AS → TGT ; TGS → tickets de service. [KRB]

Q5. Pourquoi synchroniser les horloges ?

Kerberos tolère ~5 min d'écart (clock skew) ; au-delà, plus de tickets. [KRB · STR]

Q6. Différence groupe de distribution / sécurité ?

Distribution = mails sans droits ; sécurité = permissions.

Q7. À quoi sert le filtrage SID ?

Bloquer l'usurpation de SID via SID History sur les approbations externes. [STR p.26]

Q8. Cite 4 paramètres d'une stratégie de mot de passe.

Durée max, historique, durée min, longueur min. [PROG]

Q9. Quel niveau LAN Manager est le standard actuel ?

Niveau 5 : NTLMv2 seulement, LM et NTLM refusés. [TP-LM]

Q10. Quel événement prouve qu'un compte du parent s'est authentifié chez l'enfant ?

ID 4624 (ouverture de session réussie) dans le journal Sécurité. [TP-PE]

Q11. Comment limiter une GPO aux portables ?

Filtre WMI sur Win32_SystemEnclosure (ChassisTypes = 9). [TP-GPO]

Q12. Quel ID trace les tentatives d'accès à un fichier ?

4663, après audit GPO + audit NTFS. [TP-GPO]

Révision — AAA Cisco

[AAA] Clique sur une question pour voir la réponse.

Q1. Que signifie AAA ?

Authentication, Authorization, Accounting.

Q2. Quelle commande active le modèle AAA sur un routeur Cisco ?

aaa new-model

Q3. Différence entre liste « default » et liste nommée ?

La liste default s'applique automatiquement à toutes les lignes ; une liste nommée s'applique à la main sur chaque ligne avec login authentication <nom>.

Q4. Pourquoi toujours ajouter « local » après « group tacacs+ » ?

Méthode de secours si le serveur est injoignable : on évite d'être bloqué hors de l'équipement.

Q5. Port et protocole de transport de TACACS+ ?

TCP, port 49.

Q6. Ports de RADIUS ?

UDP, 1812 (authentification) et 1813 (accounting).

Q7. Principale différence de chiffrement TACACS+ / RADIUS ?

TACACS+ chiffre tout le paquet ; RADIUS seulement le mot de passe.

Q8. Quel protocole contrôle finement les commandes CLI autorisées ?

TACACS+ (via aaa authorization commands).

Q9. Pourquoi « username … secret … » plutôt que « password » ?

« secret » chiffre le mot de passe dans la config ; « password » peut le laisser en clair (ou faiblement chiffré).

Q10. Protocole recommandé sur les vty plutôt que Telnet, et pourquoi ?

SSH : il chiffre la session, Telnet transmet les identifiants en clair.

Q11. Usage privilégié de RADIUS par rapport à TACACS+ ?

Accès réseau des utilisateurs finaux (Wi-Fi, VPN, 802.1X) ; TACACS+ sert plutôt à l'administration des équipements.

Q12. Que déclarer avant une liste d'authentification TACACS+/RADIUS ?

Le serveur lui-même (IP + clé partagée) avec tacacs server ou radius server.
