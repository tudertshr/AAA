1. Les 3 A de l'AAA

📌 Définition — AAA

AAA est un cadre (framework) de sécurité utilisé sur les équipements réseau (routeurs, switches, pare-feux) pour contrôler qui peut accéder à l'équipement, ce qu'il a le droit d'y faire, et garder une trace de ce qu'il y a fait. AAA signifie :

  • Authentication (Authentification) — Qui es-tu ?
  • Authorization (Autorisation) — Qu'as-tu le droit de faire ?
  • Accounting (Traçabilité / comptabilité) — Qu'as-tu fait, et quand ?
Les 3 A en détail
ComposantQuestion poséeCe qu'il contrôleExemple concret
AuthenticationQui es-tu ?Vérifie l'identité (identifiant + mot de passe, certificat, clé…)Login sur la console d'un routeur
AuthorizationQu'as-tu le droit de faire ?Détermine les commandes / ressources autorisées une fois authentifiéUn technicien n'a accès qu'aux commandes de niveau 1, un admin au niveau 15
AccountingQu'as-tu fait ?Journalise les connexions, la durée, les commandes exécutéesLog : « admin1 connecté à 10h02, a tapé "reload" à 10h15 »
💡 Astuce pour mémoriser l'ordre

Les 3 A s'exécutent toujours dans cet ordre logique : on vérifie l'identité (Authentication) → puis on vérifie les droits (Authorization) → puis on enregistre l'activité (Accounting). On ne peut pas autoriser quelqu'un qu'on n'a pas encore authentifié.

1.1 Pourquoi mettre en place l'AAA ?

Sans AAA, un équipement Cisco n'a par défaut qu'un simple mot de passe de ligne (line password), identique pour tout le monde, sans nom d'utilisateur, sans journalisation et sans distinction des droits. L'AAA apporte :

  • Un identifiant individuel par administrateur (traçabilité nominative).
  • Une gestion centralisée possible (un seul serveur pour tous les équipements du réseau).
  • Un contrôle fin des droits (qui peut taper quelles commandes).
  • Une journalisation de toutes les actions, utile pour les audits de sécurité.
  • Un mécanisme de secours (fallback) si le serveur d'authentification est injoignable.

2. Les lignes d'accès et les listes de méthodes (method lists)

Les lignes d'accès à un équipement Cisco
LigneCommande d'entréeUsage

VTYline vty 0 4 (ou 0 15)Accès distant (Telnet / SSH)
AUXline aux 0Accès distant par modem (rarement utilisé aujourd'hui)
📌 Définition — Liste de méthodes (method list)

Une liste de méthodes définit la séquence de méthodes d'authentification (ou d'autorisation, ou d'accounting) que le routeur doit essayer, dans l'ordre, jusqu'à ce que l'une réponde. Elle peut être :

  • default — s'applique automatiquement à toutes les lignes qui n'ont pas de liste explicite.
  • nommée (ex. CONSOLE-AUTH) — doit être appliquée manuellement sur chaque ligne avec login authentication <nom>.
aaa authentication login {default | NOM-LISTE} méthode1 [méthode2] [méthode3] …

Le routeur essaie méthode1 ; si le serveur ne répond pas (timeout), il passe à méthode2, etc. Si une méthode répond mais refuse l'accès (mauvais mot de passe), le routeur n'essaie pas la méthode suivante — l'accès est refusé.

Mots-clés de méthode les plus utilisés
Mot-cléSignification
localUtiliser la base d'utilisateurs locale (username)
group tacacs+Utiliser le(s) serveur(s) TACACS+ déclaré(s)
group radiusUtiliser le(s) serveur(s) RADIUS déclaré(s)
group NOM-GROUPEUtiliser un groupe de serveurs personnalisé (sous-ensemble de serveurs)
enableUtiliser le mot de passe enable comme méthode de secours
noneAutoriser l'accès sans authentification (à éviter, sauf test)
⚠️ Erreur fréquente

Si l'on crée une liste de méthodes nommée (pas default) mais qu'on oublie de l'appliquer sur la ligne avec login authentication <nom>, la ligne continue d'utiliser l'ancien mode (mot de passe simple ou aucune authentification) : la liste créée n'a alors aucun effet.

💡 Astuce

Toujours prévoir une méthode de secours (local ou enable) après group tacacs+ ou group radius, pour ne pas se retrouver bloqué hors de l'équipement si le serveur AAA tombe en panne.

3. AAA locale — console et lignes vty

Correspond au TP « AAA locale console & vty ». La base des utilisateurs est stockée directement dans la configuration du routeur ou du switch, sans serveur externe.

AAA locale — avantages / inconvénients
Détail
✅ AvantagesSimple à mettre en place ; fonctionne même si le réseau ou un serveur externe est en panne ; aucune dépendance externe
⚠️ InconvénientsPas centralisé (chaque équipement a sa propre base) ; pénible à maintenir sur un grand parc ; pas de journalisation centralisée des accès

3.1 Étapes de configuration pas à pas

1 Activer le modèle AAA

Sans cette commande, toutes les autres commandes aaa … sont indisponibles.

Router(config)# aaa new-model
2 Créer les comptes utilisateurs locaux

Le mot de passe doit être chiffré avec secret (jamais password en clair).

Router(config)# username admin privilege 15 secret Cisco12345
Router(config)# username technicien privilege 1 secret Tech12345
3 Créer la liste de méthodes d'authentification

Option A — liste default (s'applique automatiquement partout) :

Router(config)# aaa authentication login default local

Option B — liste nommée (contrôle plus fin, à appliquer manuellement) :

Router(config)# aaa authentication login CONSOLE-AUTH local
4 Appliquer sur la ligne console 
Router(config)# line console 0
Router(config-line)# login authentication CONSOLE-AUTH
Router(config-line)# exec-timeout 5 0

Si la liste utilisée est default, l'étape login authentication n'est pas obligatoire (elle s'applique déjà automatiquement).

5 Appliquer sur les lignes vty (accès distant) 
Router(config)# line vty 0 4
Router(config-line)# login authentication CONSOLE-AUTH
Router(config-line)# transport input ssh

Il est recommandé de limiter transport input à ssh uniquement (le Telnet transporte les identifiants en clair).

6 Vérifier la configuration 
Router# show running-config | section line
Router# show running-config | include aaa|username

Puis tester : se déconnecter et se reconnecter sur la console ou en SSH avec un des comptes créés — un couple identifiant/mot de passe doit désormais être demandé.

Exemple de configuration complète — AAA locale
Router(config)# aaa new-model
Router(config)# username admin privilege 15 secret Cisco12345
Router(config)# aaa authentication login default local
Router(config)# line console 0
Router(config-line)# exec-timeout 5 0
Router(config-line)# exit
Router(config)# line vty 0 4
Router(config-line)# transport input ssh
Router(config-line)# exit
🧠 À retenir — AAA locale
  • Toujours utiliser username … secret … (jamais password en clair).
  • aaa new-model est le préalable obligatoire à toute commande AAA.
  • Une liste default s'applique automatiquement ; une liste nommée doit être appliquée avec login authentication <nom>.

4. AAA basée serveur — TACACS+ et RADIUS (ligne console)

Correspond au TP « AAA serveur TACACS+ / RADIUS console ». L'authentification (et l'autorisation, l'accounting) n'est plus vérifiée localement mais déléguée à un serveur AAA externe (Cisco ACS / ISE, tac_plus, FreeRADIUS…).

4.1 TACACS+ vs RADIUS — les fondamentaux

TACACS+ vs RADIUS
CritèreTACACS+RADIUS
OriginePropriétaire CiscoStandard ouvert (RFC 2865/2866)
TransportTCP, port 49UDP, ports 1812 (authentification) et 1813 (accounting)
ChiffrementChiffre tout le paquetChiffre uniquement le mot de passe
Séparation des 3 AAuthentification, autorisation et accounting séparés (contrôle très fin)Authentification et autorisation combinées en une seule réponse
Autorisation par commande✅ Possible (contrôle des commandes CLI, niveau par niveau)❌ Non supporté nativement
Cas d'usage typiqueAdministration des équipements réseau (device administration : qui a le droit de taper quelles commandes)Accès réseau des utilisateurs finaux (Wi-Fi, VPN, 802.1X)

4.2 Configuration Cisco IOS — serveur TACACS+

1 Déclarer le serveur TACACS+ 
Router(config)# tacacs server SRV-TACACS
Router(config-server-tacacs)# address ipv4 192.168.1.10
Router(config-server-tacacs)# key Cisco123secret
Router(config-server-tacacs)# exit
2 (Optionnel) Regrouper le serveur dans un groupe AAA 
Router(config)# aaa group server tacacs+ TAC-GROUP
Router(config-sg-tacacs+)# server name SRV-TACACS
Router(config-sg-tacacs+)# exit
3 Activer AAA et créer la liste d'authentification 
Router(config)# aaa new-model
Router(config)# aaa authentication login default group tacacs+ local

La méthode local après group tacacs+ sert de secours si le serveur ne répond pas.

4 Appliquer sur la console 
Router(config)# line console 0
Router(config-line)# login authentication default
5 Autorisation et accounting (spécificités TACACS+) 
Router(config)# aaa authorization exec default group tacacs+ local
Router(config)# aaa authorization commands 15 default group tacacs+ local
Router(config)# aaa accounting exec default start-stop group tacacs+
Router(config)# aaa accounting commands 15 default start-stop group tacacs+

L'autorisation et l'accounting par commande (commands 15) ne fonctionnent qu'avec TACACS+.

4.3 Configuration Cisco IOS — serveur RADIUS

1 Déclarer le serveur RADIUS 
Router(config)# radius server SRV-RADIUS
Router(config-radius-server)# address ipv4 192.168.1.20 auth-port 1812 acct-port 1813
Router(config-radius-server)# key testing123
Router(config-radius-server)# exit
2 Activer AAA et créer la liste d'authentification 
Router(config)# aaa new-model
Router(config)# aaa authentication login default group radius local
3 Appliquer sur la console 
Router(config)# line console 0
Router(config-line)# login authentication default
4 Accounting avec RADIUS 
Router(config)# aaa accounting exec default start-stop group radius

Contrairement à TACACS+, RADIUS ne permet pas l'accounting détaillé par commande.

🧠 À retenir — AAA serveur
  • Toujours déclarer le serveur (tacacs server / radius server) avec sa clé partagée avant de créer la liste d'authentification.
  • Toujours garder local en méthode de secours après group tacacs+ / group radius.
  • Seul TACACS+ permet un contrôle fin des commandes autorisées par niveau de privilège.

💡 Astuce pour ne pas les confondre
  • Local = pense « pas de réseau requis, secours toujours disponible ».
  • TACACS+ = pense « Cisco + Contrôle des Commandes + Chiffré en entier » (3 C).
  • RADIUS = pense « Réseau (Wi-Fi/VPN) + Rapide (UDP) + standaRD ouvert ».

📌 Bon réflexe en Packet Tracer

Toujours tester dans cet ordre : (1) serveur AAA éteint → vérifier que le compte local de secours fonctionne toujours ; (2) serveur AAA allumé avec la bonne clé partagée → vérifier que le compte du serveur fonctionne ; (3) mauvaise clé partagée → vérifier que l'authentification échoue proprement.

⚠️ Attention avant de couper la session

Avant de valider une nouvelle configuration AAA sur les lignes vty (accès distant), garder une session déjà ouverte (ou la console) tant que la nouvelle authentification n'est pas validée — une erreur de configuration peut couper tout accès distant à l'équipement.

8. À retenir — l'essentiel du cours

🧠 Les points essentiels
  1. AAA = Authentication (qui es-tu) + Authorization (qu'as-tu le droit de faire) + Accounting (qu'as-tu fait).
  2. aaa new-model est le préalable obligatoire avant toute autre commande AAA.
  3. Une liste de méthodes essaie chaque méthode dans l'ordre, en passant à la suivante seulement si le serveur précédent ne répond pas (pas en cas de refus).
  4. AAA locale = pas de dépendance réseau, mais pas centralisée.
  5. TACACS+ (TCP/49, tout chiffré) = idéal pour l'administration des équipements, contrôle fin des commandes.
  6. RADIUS (UDP/1812-1813, mot de passe chiffré) = standard ouvert, idéal pour l'accès réseau des utilisateurs.
  7. Toujours garder une méthode de secours local après un serveur externe.

9. Révision — Questions / Réponses

Clique sur une question pour révéler la réponse.

Q1. Que signifie AAA ?
Authentication, Authorization, Accounting.
Q2. Quelle commande active le modèle AAA sur un routeur Cisco ?
aaa new-model
Q3. Quelle est la différence entre une liste de méthodes « default » et une liste nommée ?
La liste default s'applique automatiquement à toutes les lignes ; une liste nommée doit être appliquée manuellement sur chaque ligne avec « login authentication ».
Q4. Pourquoi toujours ajouter « local » après « group tacacs+ » dans une liste d'authentification ?
Pour disposer d'une méthode de secours si le serveur TACACS+ est injoignable, et éviter de se retrouver bloqué hors de l'équipement.
Q5. Sur quel port et quel protocole de transport fonctionne TACACS+ ?
TCP, port 49.
Q6. Sur quels ports fonctionne RADIUS ?
UDP, ports 1812 (authentification) et 1813 (accounting).
Q7. Quelle est la principale différence de chiffrement entre TACACS+ et RADIUS ?
TACACS+ chiffre tout le paquet ; RADIUS ne chiffre que le mot de passe.
Q8. Quel protocole permet de contrôler finement quelles commandes CLI un utilisateur peut exécuter ?
TACACS+ (via aaa authorization commands).
Q9. Pourquoi utilise-t-on « username … secret … » plutôt que « username … password … » ?
« secret » chiffre le mot de passe dans la configuration, contrairement à « password » qui peut le laisser en clair (ou faiblement chiffré selon le type).
Q10. Quel est le protocole recommandé sur les lignes vty plutôt que Telnet, et pourquoi ?
SSH, car il chiffre la session alors que Telnet transmet les identifiants en clair.
Q11. Quel type d'usage privilégie RADIUS par rapport à TACACS+ ?
L'accès réseau des utilisateurs finaux (Wi-Fi, VPN, 802.1X), alors que TACACS+ est plutôt utilisé pour l'administration des équipements réseau.
Q12. Que faut-il déclarer avant de créer une liste d'authentification utilisant un serveur TACACS+ ou RADIUS ?
Le serveur lui-même (adresse IP et clé partagée), avec « tacacs server » ou « radius server ».
